# ปรับเว็บ KNOWNA ให้ตรงกับรายงาน Ecommerce Report.pdf

วันที่: 2026-11-26
แหล่งข้อมูลหลัก: `Ecommerce Report.pdf` (ฉบับยังไม่เสร็จ 100%, 14 หน้า)

## เจตนาและเหตุผล

กลุ่มเปลี่ยนแนวธุรกิจไปแล้ว รายงานกับเว็บต้องสอดคล้องกันทุกประการ เว็บใช้ข้อมูลจาก PDF เท่านั้น
ห้ามเพิ่มหรือตกแต่งข้อมูลเอง ส่วนที่ PDF ยังไม่มี ให้ขึ้นป้าย "รอข้อมูลจากรายงาน" ไว้ แล้วเติมเมื่อ PDF เสร็จ
เว็บเป็นงานเดโมส่งอาจารย์ (ข้อมูลจำลองใน localStorage ไม่มีการจ่ายเงินจริง) เหมือนเดิม

## ข้อมูลจาก PDF ที่เว็บต้องใช้

- แบรนด์ Knowna (เว็บใช้ KNOWNA ตามโลโก้เดิม) รองเท้าผ้าใบนักเรียนชาย 3 สี: ดำ ขาว น้ำตาล (น้ำตาลสำหรับวันลูกเสือ)
- ราคา 259 บาทต่อคู่ ไม่รวมค่าจัดส่ง
- กลุ่มลูกค้า: ผู้ปกครองของเด็ก ป.1–ม.6 และนักเรียน ป.1–ม.6 (Lean Canvas)
- ระบบช่วยเลือกขนาดก่อนซื้อ 3 ส่วน: คู่มือวัดเท้าด้วยตนเอง, ตารางเทียบขนาดกับแบรนด์ที่ลูกค้าใช้อยู่, บริการแนะนำขนาดผ่านแชต
- เปลี่ยนขนาดฟรี 1 ครั้งต่อคำสั่งซื้อ แบรนด์ออกค่าส่งรองเท้าคู่ใหม่
- ขายผ่านเว็บไซต์ของแบรนด์โดยตรง ไม่มีหน้าร้าน
- ช่องทาง: เว็บไซต์และ LINE OA ของแบรนด์ (Lean Canvas), TikTok (4Ps)
- ชำระเงิน: พร้อมเพย์ ผ่าน payment gateway (ตารางต้นทุน)
- เก็บข้อมูลขนาดเท้าของบุตรหลาน และแจ้งเตือนผู้ปกครองก่อนเปิดภาคเรียน/ถึงช่วงควรเปลี่ยนไซซ์

## เป้าหมาย

1. เอาพื้นรองเท้าถอดเปลี่ยนได้ออกทั้งหมด
2. ราคา สี กลุ่มลูกค้า ช่องทาง วิธีชำระเงิน ตรงตาม PDF
3. หน้าหาไซซ์มีครบ 3 ส่วนตาม PDF
4. ระบบขอเปลี่ยนไซซ์ฟรี 1 ครั้งต่อคำสั่งซื้อ กดใช้ได้จริงในหน้าคำสั่งซื้อ
5. ข้อมูลที่เว็บเคยแต่งเอง ลบออกหรือเปลี่ยนเป็นป้าย "รอข้อมูลจากรายงาน"

## ไม่ทำ (non-goals)

- ไม่แก้ตัว PDF (กลุ่มแก้เอง)
- ไม่ทำแชตจริงหรือเชื่อม LINE OA จริง ไม่ส่งแจ้งเตือนจริง
- ไม่ทำหน้าจอมือถือเพิ่ม (desktop only ตามเดิม)

## ถือว่าล้มเหลว ถ้า

- เว็บมีตัวเลขหรือข้อกล่าวอ้างที่ไม่อยู่ใน PDF (เช่น 14 วัน, สาขาหน้าร้าน, รับประกัน 6 เดือน)
- ใช้สิทธิ์เปลี่ยนไซซ์ได้มากกว่า 1 ครั้งต่อคำสั่งซื้อ

## การเปลี่ยนแปลงทีละส่วน

### 1. เอาพื้นรองเท้าถอดเปลี่ยนได้ออก
- ลบหน้า `/soles` (`pages/Soles.tsx`), `components/SoleRail.tsx`, `SOLE` ใน `lib/catalog.ts`, `Kind = 'sole'` ใน `lib/types.ts`
- ลบเมนู ลิงก์ ข้อความ tagline "STEP UP. SWAP IT." และส่วนเรื่องพื้นในหน้าแรก ตะกร้า สินค้า ร้านค้า คำสั่งซื้อ 404
- คำสั่งซื้อตัวอย่าง (seed) ใน `lib/db.ts` ที่มีพื้นอะไหล่ ลบรายการนั้นออก
- tagline ใหม่: PDF ไม่มี จึงไม่ใส่ tagline ภาษาอังกฤษ ใช้ข้อความจาก UVP แทน: "รองเท้านักเรียนที่มาพร้อมบริการหลังการขาย เปลี่ยนรองเท้าฟรี 1 ครั้งต่อบิล"

### 2. ราคา สินค้า ค่าส่ง การชำระเงิน
- `PRODUCT.price` = 259
- `PRODUCT.details` และ `specs`: เหลือเฉพาะที่ PDF ระบุ (ผ้าใบนักเรียนชาย, 3 สี, บริการช่วยเลือกไซซ์, เปลี่ยนไซซ์ฟรี 1 ครั้ง) รายละเอียดวัสดุ/พื้น/รับประกัน ที่ PDF ไม่มี ลบออก
- ค่าส่ง: PDF บอกแค่ "ไม่รวมค่าจัดส่ง" ไม่ระบุว่าคิดลูกค้าเท่าไร และ "ส่งฟรีตามเงื่อนไขที่กำหนด" ไม่ระบุเงื่อนไข
  → ลบเงื่อนไขส่งฟรี ฿700 ค่าส่งแสดงเป็น "รอข้อมูลจากรายงาน" และไม่บวกเข้ายอดรวม (ยอดรวม = ค่าสินค้า + หมายเหตุ "ยังไม่รวมค่าจัดส่ง")
- ลบการรับที่หน้าร้าน (`STORES`, fulfilment `pickup`) เพราะ PDF บอกว่าไม่เปิดหน้าร้าน
- วิธีชำระเงิน: เหลือพร้อมเพย์อย่างเดียว (ลบบัตรและเก็บเงินปลายทาง)

### 3. กลุ่มลูกค้า ป.1–ม.6 และไซซ์
- PDF ไม่มีตารางไซซ์ ช่วงไซซ์ หรือช่วงไซซ์ตามระดับชั้น ตาราง `GRADES` เดิมเขียนว่า "from our fitting records" ซึ่งแต่งขึ้น
- ระดับชั้นที่เลือกได้: ป.1–ป.6 และ ม.1–ม.6 แต่ช่วงไซซ์ของแต่ละชั้นขึ้น "รอข้อมูลจากรายงาน"
- ช่วงไซซ์ที่ขาย: ดูคำถามที่ค้างข้อ 1

### 4. หน้าหาไซซ์ (`/size`)
สามส่วนตาม PDF:
1. **คู่มือวัดเท้าด้วยตนเอง** — โครงหัวข้อ + ช่องกรอกความยาวเท้า เนื้อหาขั้นตอนและสูตรแปลง ซม.→ไซซ์ ขึ้น "รอข้อมูลจากรายงาน" (ดูคำถามข้อ 2)
2. **ตารางเทียบขนาดกับแบรนด์อื่น** — เลือกแบรนด์ที่ใช้อยู่ (นันยาง, Breaker, Gold City, Tiger ตามรายชื่อคู่แข่งใน PDF) + ไซซ์ที่ใส่อยู่ → ไซซ์ KNOWNA; ตัวเลขเทียบ "รอข้อมูลจากรายงาน"
3. **แนะนำขนาดผ่านแชต** — ปุ่ม "ปรึกษาไซซ์ทาง LINE OA" ลิงก์ยังไม่มี แสดงป้าย "รอข้อมูลจากรายงาน"
- ข้อความ "เปลี่ยนได้ฟรีภายใน 14 วัน" เปลี่ยนเป็น "เปลี่ยนไซซ์ฟรี 1 ครั้งต่อคำสั่งซื้อ แบรนด์ออกค่าส่งคู่ใหม่"

### 5. ระบบขอเปลี่ยนไซซ์ (แบบ 1)
- `Order` เพิ่มฟิลด์ `exchange?: { lineKey: string; fromSize: number; toSize: number; requestedAt: string; timeScale }`
- `lib/api.ts` เพิ่ม `requestExchange(orderId, lineKey, toSize)` ปฏิเสธถ้าคำสั่งซื้อมี `exchange` อยู่แล้ว (1 ครั้งต่อคำสั่งซื้อ ไม่ใช่ต่อคู่) หรือคำสั่งซื้อยังไม่ส่งถึง
- หน้า `/order/:id`: ถ้าส่งถึงแล้วและยังไม่ใช้สิทธิ์ แสดงปุ่ม "ขอเปลี่ยนไซซ์ (ฟรี 1 ครั้ง)" → เลือกคู่ (ถ้ามีหลายคู่) → เลือกไซซ์ใหม่ → ยืนยัน
- หลังยืนยัน: ไทม์ไลน์ "รับคำขอแล้ว → ส่งคู่ใหม่แล้ว → ส่งถึงแล้ว" เดินตามเวลาจำลองแบบเดียวกับ `status.ts`; ปุ่มหาย ขึ้น "ใช้สิทธิ์เปลี่ยนไซซ์แล้ว"
- ระยะเวลาที่ขอได้, ค่าส่งคู่เดิมกลับ, ต้องส่งคู่เดิมคืนก่อนหรือไม่ → ข้อความ "รอข้อมูลจากรายงาน" ในกล่องเงื่อนไข และระบบยังไม่บังคับเรื่องเวลา

### 6. เก็บไซซ์ลูกและแจ้งเตือน
- หน้า `/account` เพิ่มกล่อง "ไซซ์ล่าสุดของลูก" ดึงจากคำสั่งซื้อล่าสุด (หรือไซซ์หลังเปลี่ยน)
- ข้อความ "เราจะแจ้งเตือนก่อนเปิดภาคเรียน" ช่องทาง/เวลาแจ้งเตือน "รอข้อมูลจากรายงาน" ไม่ส่งจริง

### 7. เอกสารใน repo
- อัปเดต `PRODUCT.md` ให้ตรงกับเอกสารนี้ (ตัดเรื่องพื้น, ราคา 259, ป.1–ม.6, กติกา "ข้อมูลจาก PDF เท่านั้น")

## ป้าย "รอข้อมูลจากรายงาน"
คอมโพเนนต์เดียว `<Pending />` ใน `components/ui.tsx` สีจาง มีขอบประ ใช้ทุกจุดที่ข้อมูลยังไม่มี ค้นหาง่ายตอน PDF เสร็จ
รายการทั้งหมดที่ใช้ป้ายนี้ รวบไว้ใน `lib/pending.ts` (หรือคอมเมนต์ `// PENDING-PDF`) เพื่อเติมทีเดียว

## ปล่อยให้ผู้สร้างตัดสินใจเอง
- ข้อความปุ่ม/หัวข้อ/คำอธิบายขั้นตอนการใช้เว็บ (ไม่ใช่ข้อมูลธุรกิจ)
- เลย์เอาต์และสไตล์ (คงธีมเดิม)
- รูปสินค้า AI เดิม 3 สียังใช้ได้ (ป้าย "ภาพ AI" คงไว้); รูป `brown-used`/`brown-worn` ที่ใช้เล่าเรื่องพื้นสึก เอาออกจากหน้าแรก, 404 ใช้ต่อได้

## คำถามที่ค้าง (ผู้ใช้ต้องตอบ)
1. ไซซ์ที่ขาย: PDF ไม่ระบุ จะใช้ EU 28–40 เดิมไปก่อน (เติมป้ายรอข้อมูล) หรือให้ทั้งช่องไซซ์เป็นรอข้อมูล
2. คู่มือวัดเท้า: ใช้สูตรแปลงความยาวเท้า→ไซซ์ EU ทั่วไปเดิมไปก่อน หรือเว้นว่างทั้งหมด
